## 📍 Retomar aqui

1. Perguntar ao usuário se **ouviu a voz de teste** do Piper ("Pronto. Agora eu falo pela caixa de som…").
   Foi a última coisa feita; não houve resposta.
2. Rodar com ele a **lista de testes** (abaixo) com a voz real dele. Até agora só testamos com voz sintética do espeak.
3. Ajustar o que falhar. Para ver o que o ouvido entendeu, ligar o diagnóstico (grava falas no journal, só durante o teste):
   `systemctl --user set-environment FEDORA_DEBUG=1 && systemctl --user restart fedora-assistente`
   → `journalctl --user -u fedora-assistente --since "-10min" | grep ouvido`
   → desligar: `systemctl --user unset-environment FEDORA_DEBUG && systemctl --user restart fedora-assistente`

## Como chegamos aqui (decisões)

| Decisão | Por quê |
|---|---|
| Sem OpenClaw, sem Telegram | usuário não vai usar acesso remoto; OpenClaw com Claude CLI não aplicava a sandbox |
| HUD de painéis/grafo **rejeitado e apagado** | usuário quis algo menos "caixas"; artifacts antigos deletados |
| Buraco negro no centro, info orbitando **sem caixas** | pedido do usuário; cores âmbar, nada de neon (ciano foi rejeitado como "artificial") |
| Nome **Fedora**, frase **"Ok, Fedora"** | nome escolhido pelo usuário (sistema que ele manipula); o "Ok" evita disparar quando ele fala do SO |
| Wake word via whisper (não openWakeWord) | Fedora não tem modelo pronto; assim dá pra falar nome + pedido numa frase só |
| Modelo `base` do whisper **rejeitado** para wake | alucinava "Fedora" com o prompt; ficou só o `small` (~1 s por frase) |
| Voz pelo Piper no servidor (pw-play) | `speechSynthesis` do Brave fica mudo no Linux |
| Claude com permissão `default` | o original vinha com `bypassPermissions` (perigoso com microfone aberto) |
